Did-You-Mean Teaching 404s

A caller who guesses the wrong endpoint path on a DUH service gets back a 404 that names the endpoint they meant — and recovers in exactly one retry. The contract author declares the likely wrong guesses in their OpenAPI spec; nobody writes a line of handler code.

There are two people at this boundary. The API consumer — usually an LLM agent calling the service before it has read the spec — is the one who hits the wrong path and needs the hint. The contract author is the one who predicts those wrong guesses and declares them. We meet the consumer first, because their one-retry recovery is the entire reason the feature exists. Then we meet the author's surface, then how duh generate keeps the promise.

What the caller gets

A did-you-mean path is a real, matched route whose only job is to teach. Guess it, and the generated server answers 404 with a single machine-readable hint. It never serves the operation, never redirects — it corrects you and stops.

What the API consumer sees

One request to a guessed path → one 404 carrying did_you_mean, the canonical path spelled out. Any HTTP method, same answer. That is the whole contract.

Inside — not the caller's concern

A generated case arm in the dispatch switch, emitted at duh generate time from the author's declared guess table. No runtime matching, no heuristics, no state.

The round-trip — one wrong guess, one retry

The exact reply

The 404 is an ordinary DUH Reply — same content negotiation as every other response (JSON by default, protobuf on request). The JSON form: 

{
  "code": 404,
  "message": "no such endpoint: /v1/diffs.get",
  "details": {"did_you_mean": "/v1/commits.diff"}
}

did_you_mean is always exactly one path — the single canonical endpoint the author mapped this guess to. The reply never enumerates other endpoints, and the message only ever echoes the spec-declared path, never anything from the request. The base path (/v1, from servers[0].url) is prepended to both the guessed path and the hint, just as it is for real routes.

Method-agnostic A guessed endpoint does not exist, so the method is irrelevant — GET, POST, anything on a teaching path receives the same teaching 404. Canonical routes keep their usual POST-only check; teaching paths deliberately skip it.

What is not taught — the fall-through

Teaching coverage equals the declared table, nothing more. A wrong guess the author did not predict is not this feature's concern: it matches no case, so ServeHTTP returns false and writes nothing — byte-identical to today. The binding then consults the next handler and finally the mux. That fall-through contract is load-bearing for scaffold's handler chaining and is never touched.

Matches nothing → writes nothing, ServeHTTP returns false. Terminal behavior is the deployment's concern (ENG-134).

The contract author's surface

The author never writes handler code for this. They add one extension to the spec and regenerate. The maintenance loop is deliberate and manual: observe 404s in the access log → declare the guess → regenerate.

Declaring guesses

x-duh-did-you-mean sits at the path-item level, beside the path's post: operation. Its value is a list of spec-relative paths, each beginning with / — the same form as the spec's own path keys: 

paths:
  /commits.diff:
    x-duh-did-you-mean:
      - /diffs.get
      - /revisions.compare
    post:
      ...            # the real operation, unchanged

These guesses are not contract paths, so they are exempt from the naming lint rules that govern canonical paths. They must only be well-formed (a string with a leading /) and collision-free. The extension touches server.go only — clients, protobuf/fieldmap outputs, and duh docs rendering all ignore it.

Regenerating

duh generate ./api/v1/openapi.yaml --output-dir ./gen

For each declared guess, the dispatch switch gains one arm, after the canonical arms:

case "/v1/diffs.get":
	duh.ReplyWithCode(w, r, duh.CodeNotFound,
		map[string]string{"did_you_mean": RPCCommitsDiff},
		"no such endpoint: /v1/diffs.get")
	return true

The hint references the declaring operation's own route constant (RPCCommitsDiff) — not a second string literal — so it can never drift from the real route. There is no dispatch to any handler in the arm: reply, then return true.

Before / after, for the caller Before: a guess to /v1/diffs.get returned a bare 404 with no guidance — the agent was stuck. After: the same guess returns a 404 naming /v1/commits.diff — the agent recovers on the next call.

When a declaration is rejected

duh generate fails before writing any output — exit non-zero, naming every offending path so the author fixes the spec in one pass. duh lint reports the same problems earlier, as DID_YOU_MEAN_COLLISION ERROR violations. Generate does not depend on lint having run; it enforces independently.

The invariants, and why they hold

This feature has no runtime state; the invariants are properties of the generated artifact. Each is preserved by construction, then backstopped.

InvariantHow it is preserved
Every case path is unique — canonical and teaching paths are disjoint, teaching paths pairwise distinct. Generate-time validation rejects both collision classes. Structural backstop: duplicate case literals do not compile in Go, and generated output is compile-verified in tests.
Every hint names a real route of the same spec. Structural — the hint is emitted from the declaring operation's own route constant. There is no second source to drift from; an illegal hint is unrepresentable in the template's inputs.
A teaching path never serves. Its case arm contains only the reply and return true — no dispatch to any handler exists in the arm.
An unmatched path never gets a reply, and a spec without the extension generates identical code. Structural — the template's miss path (return false) is not modified by this feature; the no-extension acceptance test pins it byte-for-byte.
Reversible Remove a did-you-mean entry and regenerate — that path returns to ordinary fall-through. Nothing persists at runtime.

Design principles & boundaries

Correct the caller, never accommodate the guess

A wrong path always replies 404 + hint and never serves. The moment a wrong path silently works, it becomes a second, undocumented API surface that can never be removed. One canonical path per operation.

The fall-through contract is inviolate

Generated ServeHTTP returns false for any unmatched path, unconditionally. Scaffold's handler chaining depends on it; no teaching mechanism may touch it.

Spec-declared and deterministic

No heuristics, generate-time or request-time. The output is a pure function of the spec; the author owns and maintains the guess table like any other part of the contract.

Zero cost to real traffic

Canonical routes gain no new code on their dispatch path; teaching paths are additional case arms in the existing string switch. Realistic tables (tens of entries) are negligible.

Deliberately out of scope

These were considered during design and rejected — they are not coming back without new evidence:

  • Any catch-all / default-arm behavior. An earlier framing proposed a runtime default: arm claiming all unmatched paths with request-time fuzzy matching. Rejected: it breaks the fall-through contract, drags in prefix-scoping and opt-out machinery, and puts a tunable heuristic on the request path.
  • Mechanical guess derivation (plural/singular, verb synonyms). Only the author knows the semantic misses that matter, and derived tables make output harder to predict.
  • Runtime fuzzy matching in any form, in generated code or in duh.go.
  • Client-side changes. Generated clients ignore the extension entirely.
The boundary with scaffold Unpredicted guesses fall through to whatever the deployment's terminal behavior is. Making that terminal response a proper DUH Reply is scaffold's job, tracked separately as ENG-134 — not this feature.
